Mission Reflection
1. Why is object storage better suited for storing millions of photos than a traditional block storage hard drive?
Object storage is better suited for storing millions of photos because it is designed to handle large amounts of unstructured data and can scale as the amount of data grows. Unlike block storage, which behaves more like a traditional hard drive with a defined capacity, object storage stores each photo as an independent object with its own metadata and unique identifier. Photos can also be accessed through an HTTP API, making object storage a good fit for web and mobile applications.
2. How did using Docker make it easier to deploy the MinIO storage server?
Docker made deploying MinIO much easier because a single command was enough to download the MinIO image, create and start the container, map the required ports, and configure the administrator credentials. I did not need to manually install MinIO or its dependencies. When I encountered errors during deployment, I could remove the existing container and restart the deployment quickly. This made the process easier to manage and troubleshoot.
3. What is a "bucket" in the context of cloud storage?
A bucket is a container used to organize and store objects in object storage. It is similar to a top-level folder, but it is specifically designed for storing objects such as images, documents, and other files. Buckets can also have their own access and security settings. In this mission, I created a bucket called client-photos and used it to store the sample file I uploaded.
4. How do you think large enterprise companies ensure their object storage data is not lost if the physical server crashes?
Large enterprises use several methods to protect object storage data from hardware failures. These include replication, which keeps multiple copies of data across different storage devices or servers, and erasure coding, which adds redundant information that can be used to reconstruct lost data. Organizations may also use versioning and regular backups to protect against accidental deletion or data corruption. These techniques help keep data available even when individual hardware components fail.

My confidence in using the Linux command line has grown through this mission. I can now run Docker commands, check running containers with docker ps, work with Git, and use terminal editors such as nano. Troubleshooting the MinIO image pull error and container name conflict also taught me to read error messages carefully and use them to identify the cause of a problem instead of simply guessing.

# Cloud Provider Comparison

## Equivalent Infrastructure Services

| Infrastructure Component | AWS | Microsoft Azure | Google Cloud Platform |
|---|---|---|---|
| Compute | EC2 (Elastic Compute Cloud) | Virtual Machines | Compute Engine |
| Storage | S3 (Simple Storage Service) | Blob Storage | Cloud Storage |
| Networking | VPC (Virtual Private Cloud) | Virtual Network (VNet) | VPC (Virtual Private Cloud) |
| Identity and Access Management (IAM) | AWS IAM | Microsoft Entra ID (formerly Azure AD) | Cloud IAM |

## Guide Questions

**1. Which cloud provider offers the broadest range of services?**

AWS is generally regarded as offering the broadest range of services, with hundreds of products spanning compute, storage, databases, machine learning, IoT, and more. As the first major cloud provider, it has had the longest runway to build out its catalog, resulting in more niche and specialized offerings than its competitors.

**2. Which cloud platform would you recommend for an organization that primarily uses Microsoft products?**

Microsoft Azure is the natural fit for an organization built around the Microsoft ecosystem. It integrates directly with tools like Active Directory, Windows Server, Microsoft 365, and .NET, which reduces compatibility friction and simplifies licensing compared to running on a different provider.

**3. Which platform is widely recognized for AI, Machine Learning, and Kubernetes services?**

Google Cloud Platform holds this reputation. Google created Kubernetes and continues to offer Google Kubernetes Engine (GKE) as one of the leading managed Kubernetes services, while its AI/ML tooling — particularly Vertex AI — is regarded as among the strongest in the industry.

**4. What similarities did you observe among the three cloud providers?**

All three providers offer functionally equivalent core services: scalable compute instances, object/blob storage, virtual networking, and identity and access management. They also share broader platform traits — pay-as-you-go pricing, globally distributed data center regions, and support for infrastructure-as-code, containerization, and hybrid or multi-cloud deployments.
